# 2026-08-13

## Campaign persistent queue implementation

- Replaced request-bound Campaign SMTP sending with a database-backed queue. The send API now validates and persists the Campaign plus delivery rows with status=queued, then returns without contacting SMTP.
- Added an application queue worker that claims pending deliveries with PostgreSQL row locks and SKIP LOCKED, sends one independent message per recipient, and records attempt count, provider message ID, sent/failed status, and safe errors.
- Added sender-level persistent pacing. The default interval is 6 seconds per configured mailbox (at most 10 sends per minute); the interval is stored as a timezone-aware timestamp and is safe across concurrent worker instances.
- Added startup recovery for stale sending rows. Interrupted deliveries older than 15 minutes become failed and can be retried explicitly.
- Added POST /api/campaigns/:id/cancel. It marks pending deliveries as cancelled and prevents the worker from claiming them; a delivery already in sending is allowed to finish.
- Added Campaign UI polling, cancelled counts, delivery cancellation status, and a Stop unsent deliveries action.
- Changed failed-delivery retry to requeue only failed rows, preserve idempotency, and wake the queue worker.
- Added isolated Playwright coverage for queue completion and stopping unsent deliveries.
