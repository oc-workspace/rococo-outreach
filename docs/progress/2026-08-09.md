## Security notes

- Do not commit SMTP passwords, authorization codes, bearer tokens, cookies, or full recipient addresses.
- Do not treat SMTP authentication as proof that Sent-folder synchronization works; the latter was confirmed manually for this controlled test.
- Do not add automatic port failover during a send, because a retry on another port could create duplicate mail.

## Formal campaign-send API slice

- Added migration `20260809123000_register_verified_winnie_sender` to register the tested mailbox as an active, domain-verified, sender-verified `EmailSender`.
- Added protected `POST /api/campaigns/send` for the development environment.
- The API uses the server-side Bearer token gate and does not expose SMTP credentials.
- Server validation requires an active verified sender, exact equality between selected sender and the connected SMTP mailbox, a matching Reply-To, unique valid recipients, rendered content, and a maximum of 50 recipients.
- The API creates the Campaign and delivery rows before sending, sends one independent SMTP message per delivery, and records `sent`/`failed`, provider message ID, safe error summary, and timestamps.
- Automatic retry and port failover are intentionally not included.
- Local production build passed with the new route.
- No new campaign email was sent during this implementation slice.

The API is ready for protected endpoint smoke tests after deployment. A real campaign send should only be attempted after reviewing the payload and confirming the selected sender is the intended mailbox.

## Send reliability hardening

- Added a unique nullable `idempotencyKey` to `EmailCampaign`.
- Added migration `20260809143000_add_campaign_idempotency_key`.
- `POST /api/campaigns/send` now requires a valid `Idempotency-Key` header.
- Duplicate requests return the existing Campaign instead of creating a second Campaign or sending duplicate mail, including the concurrent-create race path.
- The frontend generates one key at the second-confirmation step and reuses it if the request needs to be retried.

## Manual retry for failed deliveries

- Added delivery attempt tracking with `attemptCount` and `lastAttemptAt`.
- Added `EmailCampaignRetry` records with a unique idempotency key so a repeated retry request cannot resend the same failed delivery set.
- Added protected `POST /api/campaigns/:id/retry-failed`.
- Retry only targets deliveries currently marked `failed`, claims each row before sending, updates its status/provider message ID/error, and recomputes Campaign totals.
- Added a Campaign History action to retry failed recipients and show per-delivery attempt counts.
- Automatic retry and SMTP port failover remain disabled; retries are explicit operator actions.
- Local production build passed. No new email was sent during this implementation slice.
